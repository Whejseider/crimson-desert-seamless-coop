# Port 1.0.0.3479 -> 1.0.0.3527 (2026-11-04)

Steam updated the game on 2026-11-04 00:15 to 1.0.0.3527 (PE 0x6AEA07A6, SizeOfImage 0x13EB2000, 328,899,480 bytes),
in the middle of the story sync release run. The mod switched itself off as designed. Both exes are in
build/exe-archive (git-ignored), which made this port a mapping job instead of a search.

## How each value was found (build/port3527)
- `portmap.py code(rva)`: the instructions at the old address, relative operands masked (capstone: branch targets,
  rip-relative displacements), searched in the new image's code; the hit nearest the old address. 40 of 43 code
  sites: exactly one hit.
- `portmap.py data(rva)`: a global or vtable is mapped through the code that addresses it: up to 8 rip-relative
  references in the old image, each mapped with code(), decoded in the new one; the targets agree (8/8 for
  WorldSystem). The five vtables verify-port checks through RTTI came out identical.
- Template copies (kActionLayersAdvance, kPending): their bytes occur 227 times, and the nearest hit (+0x40) was
  WRONG. Mapped through the unique code that takes their address: +0x33B0, the 0x670 gap between them kept.
- CC slots 16 / 18 / 24 read from the CharacterControl vtable; NormalMovementMethod slot 2 = the movement step.
- Heads with an embedded rip-relative offset re-recorded (minimap decide; the AI battle-type jmp; verify-port's
  copies of the minimap and input-mode push heads).
- `map_all.py` (every address, table + map_3527.json), `gen_offsets.py` (offsets_3527.h), `retarget.py` (the
  namespace in 21 files, horse_diag / load_trace sites, the version texts), `retarget_verify.py` (verify-port.ps1).
