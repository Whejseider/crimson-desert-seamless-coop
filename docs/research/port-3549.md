# Port 1.0.0.3527 -> 1.0.0.3549 (2026-11-04)

Steam updated the game on 2026-11-04 (evening) to 1.0.0.3549, title screen "GameVersion: 2.04.07" (PE 0x6AEB7D59,
SizeOfImage 0x13CFF000, 327,116,696 bytes; exe kept in build/exe-archive). The released Co-op+ (69b9b13e, made for
3527) switches itself off on it, as designed.

## What changed in the exe
- The game's own code did not move. In the main code section 0.075% of the bytes differ, nearly all of them 2-3
  byte call targets into the copy protection. The protection itself is re-encrypted (97% of its section differs)
  and laid out again: the AI battle-type entry used to jump into one protected section, now into another.
- Every address the mod uses maps to itself: build/port3549/map_all.py (64 addresses from map_3527.json plus the
  quest server sites), all +0 with identical head bytes. So src/mod/game/offsets_3549.h re-exports the whole 3527
  table and only sets the new PE timestamp and image size (gen_3549.py also pointed the 24 users at build_3549 and
  changed the version texts).
- One head that is not in the offsets table did change: aggro_test.cpp's CheckAIBattleType entry is a 5-byte
  `jmp` into the protection, so its rel32 is new on every build (3527 E9 6B 2F BF 0A -> 3549 E9 CB 62 B8 0A).
  Same function: the vtable slot 0x5C7CAD8 still holds exe+0x24C1C60 (build/port3549/vtref.py, dis2.py).
  Next port: map_all.py must include it (the 3527 port notes listed it too).

  kImageBase missing and a stale minimap head.

## Found while porting (fixed in this build)
1. Loads ~50 s longer since the slow-motion block (affects the released 69b9b13e on 3527 too). The block read every
   received packet with game::safe_read, a VirtualQuery per packet. During a load the game streams thousands of
   messages while its loader threads allocate memory, and those calls waited on them: from "in world" to the
   server's LoadingCompleteAck took 37-63 s in every run since 20:58 (the first run with the block), against 12 s in
   the ~45 runs before it. The client sent nothing for ~48 s mid-load (build/port3549/loadtl.py). The filter now
   reads the game's buffer directly like the other filters in the chain: 12 s again (p49d, ls49c, fb49b).
   Rule: nothing on the per-packet path may call safe_read / VirtualQuery.
2. Horse copy turned off for the whole session after a transient hook failure. The crash guards' first install
   sometimes fails (1 launch in 2 here; reason 1.3 = IP-relative instruction out of range: the hook's trampoline
   landed beyond 2 GB from the short jump it relocates) and the retry 2 s later succeeds. But the wall-climb setup
   had already tried the guards itself before the retries, and on that failure switched the horse copy off for
   good and skipped the mount fix. The mount/dismount fix is now its own step (puppet_install_ride_fix), run after
   the guard tries (fb49b: guards on try 2, RideOn fix installed, horse on).
3. Hook failures now log the reason under MidHook's own (mod/hook_error.h): "safetyhook error 1.3".
